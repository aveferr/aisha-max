# Развёртывание на VPS (Beget и любой другой Ubuntu-сервер)

Итог: сайт и мини-приложение по постоянному HTTPS-адресу, бот работает круглосуточно, ноутбук не нужен.

## Что понадобится

- VPS: Ubuntu 22.04 или 24.04, **от 2 ГБ памяти**, 1–2 процессора, 20 ГБ диска.
- IP-адрес сервера и пароль пользователя `root` (приходят после заказа).
- Домен. Свой не обязателен: подойдёт адрес вида `203-0-113-10.sslip.io`, где цифры — IP сервера
  через дефисы. Он ведёт на ваш IP, а сертификат выдаётся автоматически. MAX принимает такие адреса
  (разрешены буквы, цифры, точки и дефисы).

## 1. Подключитесь к серверу

С вашего компьютера в PowerShell:

    ssh root@IP_СЕРВЕРА

## 2. Установите Docker и закройте лишние порты

    curl -fsSL https://get.docker.com | sh
    ufw allow 22
    ufw allow 80
    ufw allow 443
    ufw --force enable

Проверка: `docker compose version` должна показать версию 2.24.4 или новее.

## 3. Скопируйте проект на сервер

На вашем компьютере, из папки проекта:

    cd D:\учеба\казань\afisha-max
    scp -r . root@IP_СЕРВЕРА:/opt/afisha

Вместе с проектом уедут `.env` (токен) и папка `certs` (сертификат Минцифры). Токен никому не пересылайте,
кроме своего сервера.

## 4. Настройте .env на сервере

    ssh root@IP_СЕРВЕРА
    cd /opt/afisha
    nano .env

Проверьте или добавьте строки:

    MAX_BOT_TOKEN=...
    MAX_BOT_USERNAME=...
    MAX_CA_BUNDLE=/certs/имя_вашего_файла
    DOMAIN=203-0-113-10.sslip.io
    CORS_ORIGINS=https://203-0-113-10.sslip.io
    POSTGRES_PASSWORD=придумайте_длинный_пароль
    DEV_AUTH_ENABLED=false

Сохранить в nano: `Ctrl+O`, `Enter`, выйти `Ctrl+X`.

Про `DEV_AUTH_ENABLED`: `true` позволяет заходить без MAX под любым номером (`X-Dev-User-Id`). На публичном
сервере лучше `false`. Оставляйте `true`, только если проверяющие ходят в живой API по `DATA-API.yaml`.

## 5. Запустите

    docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build

Первый раз сборка занимает несколько минут. Проверка:

    docker compose -f docker-compose.yml -f docker-compose.prod.yml ps
    docker compose -f docker-compose.yml -f docker-compose.prod.yml logs bot

Откройте `https://ВАШ_ДОМЕН/` в браузере: сайт должен открыться с замочком. Без `?dev=1` он попросит войти через MAX,
это нормально.

## 6. Подключите адрес в MAX

business.max.ru/self → Чат-боты → ваш бот → ⋮ → Настройки → вставьте `https://ВАШ_ДОМЕН` → Сохранить.
Адрес больше не меняется.

## Обслуживание

Обновить проект после правок: снова `scp -r . root@IP:/opt/afisha` и команда запуска из пункта 5.
Остановить: `docker compose -f docker-compose.yml -f docker-compose.prod.yml down` (данные сохраняются).

## Если что-то не так

- **Сайт не открывается, в логах Caddy ошибка про сертификат.** Проверьте, что порты 80 и 443 открыты у
  провайдера и в `ufw`, а DOMAIN написан без `https://`. Если сертификат для `sslip.io` не выдаётся (у общего
  домена бывают лимиты), возьмите свой недорогой домен и направьте A-запись на IP сервера.
  Логи: `docker compose -f docker-compose.yml -f docker-compose.prod.yml logs caddy`.
- **Бот молчит.** `logs bot`: чаще всего неверный токен или не указан `MAX_CA_BUNDLE`.
- **Токен нельзя запускать в двух местах.** Остановите бота на ноутбуке (`docker compose down`), иначе они будут
  мешать друг другу.
- **Не хватает памяти.** Смотрите `docker stats`; при 1 ГБ проект не поместится, нужен тариф от 2 ГБ.

## Особенности VK Cloud

Шаги те же, но отличается вход и сеть:

- Сервер создаётся в кабинете cloud.vk.ru: **Облачные вычисления → Виртуальные машины → Создать**.
  ОС Ubuntu 22.04, шаблон с **2 ГБ памяти и больше**, сеть **«Внешняя сеть (internet)»** (так сервер получит публичный IP).
  В поле «Ключ виртуальной машины» выберите «Создать новый ключ»: файл ключа скачается на компьютер, потеряете —
  не войдёте.
- Вход не по паролю и не под `root`, а по ключу под пользователем `ubuntu`:

      ssh -i путь\к\ключу.pem ubuntu@IP_СЕРВЕРА

  Если Windows ругается «UNPROTECTED PRIVATE KEY FILE», ограничьте права на файл:

      icacls путь\к\ключу.pem /inheritance:r
      icacls путь\к\ключу.pem /grant:r "$($env:USERNAME):(R)"

- Команды на сервере с `sudo`: `curl -fsSL https://get.docker.com | sudo sh`, `sudo docker compose ...`.
  Проект копируйте в домашнюю папку: `scp -i путь\к\ключу.pem -r . ubuntu@IP_СЕРВЕРА:~/afisha`, затем `cd ~/afisha`.
- Порты 80 и 443 открываются не через `ufw`, а в **группе безопасности** виртуальной машины (раздел сети/firewall
  в кабинете): добавьте входящие правила TCP 22, 80 и 443 с источником `0.0.0.0/0`. Без них сайт снаружи не откроется
  и Caddy не получит сертификат.

## Yandex Cloud (вход без root, только по SSH-ключу)

В Yandex Cloud пароля нет, а пользователь `root` не используется. Отличия от инструкции выше:

1. **Ключ.** В PowerShell: `ssh-keygen -t ed25519` (три раза Enter). Открытая часть лежит в
   `C:\Users\<вы>\.ssh\id_ed25519.pub`: её содержимое вставляется в форму создания машины.
2. **Машина.** Compute Cloud → «Создать виртуальную машину»: образ Ubuntu 24.04, 2 vCPU с гарантированной долей 20%,
   **2 ГБ RAM**, диск 20 ГБ, публичный адрес, свой логин (например `deploy`) и ключ.
3. **Подключение:** `ssh deploy@IP_СЕРВЕРА`. Все команды администратора — с `sudo`.
4. **Docker:**

       curl -fsSL https://get.docker.com | sudo sh
       sudo usermod -aG docker $USER

   После этого выйдите (`exit`) и подключитесь снова, чтобы `docker` заработал без `sudo`.
5. **Порты.** Вместо `ufw` откройте входящий трафик на 22, 80 и 443 в **группе безопасности** машины.
6. **Копирование проекта:** `scp -r . deploy@IP_СЕРВЕРА:~/afisha`, затем `cd ~/afisha` и команды из пунктов 4–5 выше.
7. **Постоянный адрес.** Публичный IP по умолчанию меняется при остановке машины: зарезервируйте его (сервис
   Virtual Private Cloud → IP-адреса), иначе после остановки придётся менять DOMAIN и адрес в MAX.
8. **После проверки удалите машину, диск и зарезервированный IP**, иначе деньги продолжат списываться.
